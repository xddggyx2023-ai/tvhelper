# 智能电视助手 — 可行性评估与技术路线（第一版）

日期：2026-11-23
状态：调研结论，未开始写代码

---

## 一、结论先说

**技术上能做，而且不难做。真正难的不是代码，是电视那边的三个"人为限制"。**

市面上的技术底座已经成熟：手机上不 root、不装 adb 命令，直接用 Kotlin 库跟电视的 adb 服务走网络协议，就能装应用、执行命令、读应用列表。这一步有 3 个开源库可用，许可证都允许闭源商用。

但是：**"普通用户能自己搞定"这件事，目前没有任何产品真正解决**，这才是这个项目的价值所在，也是唯一的护城河。

## 二、四个硬门槛（必须提前接受，否则产品会翻车）

### 门槛 1：ADB 开关必须用户自己在电视上打开，我们只能"教"
各品牌入口不一样，部分品牌藏在工厂菜单里（创维/酷开要遥控器按「上上下下左右左右」）。APP 无法代替这一步，只能做逐步图文/视频引导。做不好，用户第一步就流失。

### 门槛 2：第一次连接，电视会弹"允许调试"的确认框
**必须用遥控器在电视上点"允许"**，手机这头做不了。用户看不到电视画面时就以为是 APP 连不上。
→ 产品必须把这一步做成一个专门的中间页：「请现在拿起遥控器，看电视屏幕，点『允许』」，并做倒计时/重试。

### 门槛 3：不是所有电视开了 ADB 就开 5555 端口
大部分国产电视（小米、索尼、TCL/雷鸟、海信部分机型）开启 ADB 调试后，电视会在 5555 端口监听，手机可直接连。
**但也有机型只有插 USB 时才开网络调试**。这类机型手机上无解，只能告诉用户「你这台不支持，改用 U 盘/电视助手」，不能骗人说能用。
→ 第一版必须做"失败就说失败"，并且在知识库里标出「已确认不支持」的机型。

### 门槛 4：禁用预装软件有变砖风险
`pm disable-user` 在部分电视上会被系统拒绝（权限不够）；**更危险的是禁错了包**（系统桌面、SystemUI、设置），电视会黑屏或开不了机，只能恢复出厂。
→ 硬性设计：
- 只允许禁用白名单里"确认安全"的包（视频平台、广告服务等），系统关键包在界面上直接不给按钮；
- 每次禁用前弹窗写明后果；
- 必须有「一键全部恢复」，并把操作记录存在本地，即使 APP 重装也能查到；
- 禁止做「卸载系统应用」，只做「禁用/恢复」。

## 三、现成竞品（必须先看清，否则白做）

**甲壳虫 ADB 助手**（苏州嫩芽，38MB，免费）：手机连电视/车机，装应用、卸应用、传文件、投屏、跑命令，功能上就是本项目的"技术层"。已经有大量教程在推它。

结论：**"手机端 ADB 工具"这个功能点已经没有空白了。** 如果只做工具，用户没有理由换成你的。

你能赢的地方只可能是：
1. **知道电视型号后自动给出这台电视的开启路径**（甲壳虫不教这些）；
2. **每一步都有"你现在应该看到什么"的截图对照**，用户不会卡住；
3. **失败诊断**（连不上/装不上/被拦截），直接给原因和下一步；
4. 禁用预装应用时**默认安全**（白名单+一键恢复），让小白敢按。

也就是：**卖"带路"，不卖"工具"**。这一点要写进产品定位，第一版所有界面设计都围绕它。

## 四、可直接复用的开源件（都已核对许可证）

| 库 | 用途 | 许可证 | 评价 |
|---|---|---|---|
| [Kadb](https://github.com/flyfishxu/Kadb) | 纯 Kotlin 的 ADB 客户端：连接、配对、shell、装 APK、传文件 | Apache-2.0（可闭源商用） | **首选**。Maven Central 直接依赖，minSdk 23，体积小 |
| [dadb](https://github.com/mobile-dev-inc/dadb) | 同类，1227 星，项目活跃 | Apache-2.0 | 备选。连真机需要 adb server，配对支持弱，因此不做首选 |
| [libadb-android](https://github.com/MuntashirAkon/libadb-android) | 同类 + USB 连接，AppManager 在用 | GPL-3.0 / Apache-2.0 双许可 | 需要 USB 连电视时用它；走 Apache 分支 |
| [android-wireless-debug](https://github.com/xswl369/android-wireless-debug) | Android 11+ 无线调试自动配对（SPAKE2）实现 | Apache-2.0 | 参考实现，只在新电视上需要 |
| [aerial-tv / adb-by-brand.md](https://github.com/pengchujin/aerial-tv/blob/master/docs/devices/adb-by-brand.md) | 各品牌电视开 ADB 的入口整理 | 需再看 | **知识库的起始素材**，可省几天整理时间 |
| [glasstv / tv-adb-guide.md](https://github.com/jichun29/glasstv/blob/main/docs/tv-adb-guide.md) | 同上，更细 | 需再看 | 交叉核对用 |

**Android 端不需要 root**，只需 `INTERNET` + `ACCESS_NETWORK_STATE` + `ACCESS_WIFI_STATE` +（mDNS 发现用）`CHANGE_WIFI_MULTICAST_STATE`。权限很少，对过安全检测有利。

## 五、建议的技术方案

**App 形态**：Kotlin + Jetpack Compose，minSdk 24（Android 7，覆盖绝大多数在用电视和手机），targetSdk 35。

**连接流程（这是产品的核心，不是附属功能）**
1. 手机和电视在同一 Wi-Fi（APP 自动判断，不在同一网就提示换网）。
2. **双通道发现**：
   - mDNS 广播发现（`_adb-tls-connect._tcp`），只对 Android 11+ 电视有效；
   - **局域网 5555 端口并发扫描**（254 个地址，约 3~6 秒），对老电视有效 —— 这条是主力，不能省。
3. 扫到后做一次 ADB 握手，读 `ro.product.model` / `ro.product.brand` / `ro.build.version.release`：
   - 用来**确认这真是电视不是别的设备**；
   - 用来**自动识别品牌型号**，比让用户手输准得多。用户原本设计的"输入品牌型号"退化成兜底。
4. 电视弹授权框 → APP 显示第 2 个门槛的引导页。
5. 连上后进主页，按能力显示：装应用 / 应用列表 / 禁用恢复 / 换桌面 / 诊断。

**禁用与恢复**
- 禁用：`pm disable-user --user 0 <包名>`
- 恢复：`pm enable <包名>`
- 每次执行后**回读状态**确认真的生效，失败就明确报错，绝不显示成功。

**换桌面**
- 先尝试 `cmd package set-home-activity`；不生效就退化成「引导用户自己在电视设置里改」，不硬来。

**知识库**
- 本地 JSON/SQLite：品牌 → 型号段 → 开启路径（步骤、遥控器按键序列、风险提示、是否确认支持 5555）。
- 结构设计成可增量更新（后续从官网拉一个 JSON 差量包），第一版不联网。

**"轻量 AI"的真实做法**
第一版**不要做聊天框**。做"关键词 + 型号匹配"的规则引擎：
- 用户输入"小米电视 4A 装不上软件" → 抽出品牌=小米、型号=4A、问题=安装失败 → 命中知识库条目 → 输出步骤卡片；
- 这种做法的准确率远高于小模型胡说，成本为零，且**不会瞎编危险命令**。
- 后续要接大模型，只接在"诊断自由问答"这一个入口，并且让模型只做"选知识库条目"，不让它直接生成命令。

## 六、对原计划的 3 处调整建议

1. **顺序调整**：先做「连上 + 装一个 APK」的垂直验证，再做知识库和界面。
   理由：如果目标电视根本不监听 5555，前面整理的所有教程都用不上。先验证 1 台，再铺内容。
2. **"输入品牌型号"改为自动识别为主**：连上就能读到型号，手输只做兜底。
3. **"AI 助手"降级为"智能引导"**：宣传上不要暗示它是 ChatGPT，否则用户期待错位，评价会很难看。

## 七、体积真相

Compose + 文字知识库，APK 大约 **8~15MB**。要到 30~50MB 只能塞教程截图或视频。
建议：**目标 15MB 以内**。体积小 = 用户敢下、审核少问、更新快。你原定 30~50MB 不是做不到，是没必要。

---

## 八、发布与安全（必须提前给用户打预防针）

1. **自签名 APK 在国产手机上必然弹"未知来源/风险应用"警告**，华为还要过"纯净模式"。这不是 bug，是系统机制。缓解手段：
   - 官网提供 SHA256 校验值和签名指纹；
   - 页面上明确"为什么需要这些权限"；
   - 提供引导图文（如何允许安装）。
2. **"禁用预装应用"这类功能容易被安全软件标记为"风险工具"**，官网直发是对的，别指望商店。
3. 免费自签名够用。**关键：以后所有版本必须用同一个密钥**，丢了这个 key，老用户就无法覆盖升级。→ 密钥文件 + 密码要备份两份（加密后放两个地方）。

## 九、第一周能验证什么（建议的下一步）

最小验证目标（1 台真电视）：
1. 手机 APP 扫到电视 IP；
2. 完成 ADB 连接（含电视端遥控器点"允许"）；
3. 读到电视品牌/型号/系统版本；
4. 装进去一个测试 APK；
5. 列出应用、禁用 1 个无关紧要的包、再恢复。

这 5 步跑通，项目就成立；跑不通，就换目标机型或改做"U 盘/电视助手"路线。**在这 5 步跑通之前，不要写界面、不要整理大批教程。**
